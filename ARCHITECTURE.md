# Architecture

Why this site is built the way it is — including the decisions that were wrong the first time, since those are the ones worth writing down.

> This is the *rationale*. For the working instructions a contributor needs, see [CLAUDE.md](CLAUDE.md).

---

## 1. Content is a layer, not a detail

Every piece of copy and data lives in `src/content/`. Components import and render; they hold no content arrays.

That sounds like ordinary hygiene until you count the consumers. A single project entry feeds:

| Consumer | Derived how |
|---|---|
| The Work section | Rendered directly |
| Both terminals | `terminal-fs.ts` maps content into `~/projects` |
| The SQL console | `sql-engine.ts` builds relations from the same arrays |
| The API console | Handlers read the modules, so responses can't drift |
| BM25 search | `search-index.ts` indexes the same text |
| `neofetch` | Counts projects at run time |
| The résumé | `content/resume.ts` derives titles, clients, years, stacks by id |

The rule this enforces: **a query result must not be able to disagree with the page**. An exhibit that says something different from the section above it is worse than no exhibit — it turns a demonstration into a liability.

The résumé is the interesting edge. A CV is a *curated* view, not a dump, so `resume.ts` splits the difference: **facts are derived, prose is authored.** Titles and years come from the modules and cannot drift; the condensed body text is written there, because a CV line and a case-study paragraph are genuinely different objects. Every omission is explicit and carries the reason next to it.

## 2. Scroll and motion: three layers, and staying inside them

The pre-rebuild version had every section rolling its own scroll handling. Now:

1. **Lenis owns scrolling** — set up once with `autoRaf: false` and driven off framer-motion's `frame` loop. Two tickers competing for the same frame is visible as jitter on anything scroll-linked.
2. **`<Reveal>` / `<Stagger>` are the only scroll-reveal primitives**, and reveals are one-way (`viewport={{ once: true }}`).
3. **Scroll-linked transforms only where earned** — hero parallax, the experience rail fill, the projects stack.

### Two things that had to be learned the hard way

**`allowNestedScroll: true` is load-bearing.** Lenis intercepts wheel events at the window and drives the page with them, so by default *nothing nested can scroll itself*. That silently froze the lab's execution log, the terminal buffer, every dialog, the ⌘K list and the mobile drawer. The obvious fix — tagging each container with `data-lenis-prevent` — is worse: it disables Lenis for the whole subtree, so hitting the bottom of an inner pane stops the page scrolling until the pointer leaves.

**Reveals used to be `useScroll` → `useTransform(opacity)` per section.** That faded sections back out at scroll extremes, so on a short viewport content could be invisible while it was on screen. One-way reveals fixed a bug, not just a style.

## 3. The hero has been through three occupants

The history is the point.

- **Mock interfaces** — a fake terminal, a fake n8n canvas, a floating "tech stack" card. Rejected on sight as looking AI-generated, and rightly: stacked glassmorphic panels imitating product screenshots are the visual signature of a generated mockup. It was decoration pretending to be evidence.
- **`AsciiSculpture`** — a genuine software 3D renderer printing a rotating torus to characters. Well built, and still cut. **It was impressive but it wasn't evidence** — the same objection as the mock panels, wearing better clothes.
- **`HeroTerminal`** — the current occupant, and the distinction that matters: *this one is the product.* You can type into it.

It runs `neofetch` for you on arrival, and **the opening buffer is generated by `runCommand`, never transcribed.** A hardcoded copy would be a screenshot of a command rather than the command — the exact thing the terminal exists to disprove — and it would go stale the moment a project was added.

There is no photograph of Sahil anywhere on the site, by request. The About section renders a typographic index of the stack layers instead.

## 4. Failure containment

A white page is the worst failure mode a portfolio has. Three mechanisms trade it for something legible:

**Storage can throw on read.** When a browser blocks site data, *accessing the property itself* raises `SecurityError`. An unguarded read in an effect throws during commit, React unmounts the root, and the whole site goes blank over a cosmetic preference. This actually happened, via the preloader's session gate. Everything now goes through `lib/safe-storage.ts`.

**A failed dynamic import self-heals once.** A tab left open across a deploy still holds the old build's module graph, so `/assets/Lab-<oldhash>.js` 404s — that visitor gets an error screen for a site working fine for everyone else. `lazyRoute()` catches the rejection and reloads once, guarded by a session flag. **The flag is the important half:** without it, a genuinely missing chunk reloads forever.

**There are two error boundaries, and the inner one resets on navigation.** Without a `resetKey`, a boundary that catches once shows its fallback for the life of the mount — and since the outer instance sits above `<Routes>`, one transient failure makes *every* page look broken.

## 5. Verifying without a test framework

There is no test runner and no typecheck script, and `strict: false` means the compiler catches very little. Two practices fill the gap.

### Engines are pure so they can be asserted in Node

Every `lib/` module behind an exhibit is free of DOM access precisely so it can be bundled with esbuild and run under plain Node. **471 assertions across 16 engines.** What that has actually caught:

- `>=` comparing lexically instead of numerically in the SQL engine
- a stemmer eating `node.js` (stemming it gives `node.j`, which matches nothing)
- spurious `UNIQUE` constraints inferred from five coincidentally-distinct rows
- primary keys picked from dates that happened not to repeat
- an infinite Sudoku solve on a contradictory board — it hung the test run
- a ReDoS screen that refused its own reference solution
- five hand-counted par values that were simply wrong

Where randomness is involved the RNG is injected, so tests can pin a seed.

### The browser is driven over CDP, with no Playwright

Chrome is already installed. `--headless=new --dump-dom` answers "did this route mount" in about ten seconds, and for failures that only appear on *interaction*, `--remote-debugging-port` plus a ~50-line script using Node's built-in `WebSocket` needs no dependencies at all.

This is how the `TypeError: destroy is not a function` bug was pinned to an effect rather than guessed at. The cause was:

```js
useEffect(() => window.scrollTo(0, 0), [])
```

A concise-body arrow returns the expression's value; React stores that as the cleanup. `window.scrollTo` is documented as returning undefined — and hands back an object in Chrome 150. On unmount React called it, and the route went down. Nothing in the lint config catches this.

Two habits came out of that work:

- **Always relaunch the browser after editing**, or you are testing the pre-fix module and will read an HMR failure as a real one.
- **`body { overflow-x: clip }` hides responsive bugs**, so `scrollWidth === clientWidth` proves nothing. Measure element rects against the viewport instead. That is how the navbar overflowing to 959px inside a 768px viewport was found — clipped, invisible, and silently costing the Résumé button and ⌘K on every tablet.

## 6. Things deliberately *not* done

Negative space is design too.

- **No animation dependency for `/motion`.** The page's whole argument is that these are fifteen lines each; installing a kit to service it collapses the claim.
- **No gradient-blob aurora.** It is the single most copied background on the web, and a page arguing "built, not installed" cannot open on the one thing every template ships. Its replacement resamples a real noise field.
- **No stock photography.** Absent a screenshot, project cards draw a deterministic gradient monogram from the project id.
- **The three ERP client sites are named but never linked.** A link would imply you can go and see the ERP; you can't — they're internal systems.
- **Every value in the ERP demo and schema explorer is invented**, and labelled as sample data in two places. A demo a visitor could mistake for real client records is a liability.
- **PDF export is `window.print()`, never jsPDF or html2canvas.** Both rasterise, producing a résumé no applicant-tracking system can read.
